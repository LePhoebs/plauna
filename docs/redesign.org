#+title: Redesign of the Plauna web interface

The web interface is reworked in four steps, each deployable on its own. This file records the
target structure, the decisions taken and the ideas kept for later, so later steps start from the
same plan.

* Target structure

A sidebar (desktop) and a bar at the bottom (phone) replace the old top navigation and the
"Administration" link list. Six areas, ordered by what the user does:

| Area       | Contains                                                                                   | Formerly                                         |
|------------+--------------------------------------------------------------------------------------------+--------------------------------------------------|
| E-mails    | List with search, filters, saved views, bulk actions; detail page                          | Emails, e-mail detail                            |
| Categories | Overview; per category a page with e-mails, suggestions and settings                       | Administration → Categories, list's suggest filter |
| Model      | Training status and "Train now", languages, thresholds, model type, scoring of the e-mails | List's training card, Languages, parts of Preferences |
| Accounts   | IMAP accounts with status; per account connection, folder parsing, problems, runs          | Administration → IMAP Connections, providers     |
| Statistics | As before                                                                                   | Statistics                                       |
| System     | General settings, login (password, mTLS), database, mbox import, diagnostics               | Preferences, Login Settings, mTLS, Database, REPL, thread dump |

Old addresses keep working through redirects (bookmarks, the installed web app).

* Design language

- Neutral surfaces with a slight red tint; the burgundy of the logo (=#8c0327=) is the only accent.
  Category colors appear as a dot or pill, no longer as a tint of the whole row.
- System font, 13.5 px base size, dense rows, tabular figures.
- Own daisyUI themes =plauna= (light) and =plauna-dark= replace =autumn=; Plauna follows the system
  setting.
- Messages appear as small toasts at the bottom right; errors stay until closed. The connection
  status sits at the bottom of the sidebar.
- Technology stays: Selmer templates, Tailwind, daisyUI, a little plain JavaScript. No framework, no
  CDN.

* Decisions

- *Language*: the interface is bilingual, German and English. The language follows the browser by
  default and can be fixed in the sidebar. Texts live in =resources/i18n/en.edn= and =de.edn=;
  templates use ={% t key %}=. Pages are translated when their step reworks them, so until step 4
  some pages are still English only.
- *E-mail detail*: stays a page of its own for now (see "Ideas for later").
- *Column filters*: the Subject/From/To/Category filters stay in the table header, but they are only
  active after the "Filter" button of the toolbar was pressed (step 2).

* Steps

1. *Shell* (done): layout, navigation, themes, toasts; the Categories and Model areas; the
   suggestion filter moves from the e-mail list to the category page; the training card moves from
   the list to Model; old addresses redirect; bilingual texts for the shell and the new pages
   (category page, Model, System). The category page is a first version: it counts the suggestions
   per method and opens them in the e-mail list; step 3 turns it into the page with tabs.
2. *E-mails* (done): toolbar with search, date range and views (All, Uncategorized, Assigned by the
   model, With category and language) and filter chips; header filters behind the "Filter" button;
   compact rows with sender, subject, category pill (dashed with its probability when the model
   assigned it) and short date; the language column moved to the detail page; a floating bulk bar;
   phone: two-line entries. The detail page got the new layout (contents left, category and
   language, model scores and delete on the right). The bottom sheet for the category on the phone
   uses the bulk bar's native select instead.
3. *Categories and Model* (done): category overview (counts, folder, flag, time until the trash, a
   "New category" form) and the category page with the tabs Suggestions, E-mails and Settings;
   suggestions grouped by sender (domain) with "Assign all" and per-e-mail ticks; the Model page
   bundles the training and its daily time, languages, thresholds, the model type and the scoring;
   System → General keeps time zone, intervals and log level. /admin/languages redirects to
   /model#languages.
4. *Accounts and System* (done): the accounts list with a status dot and its actions; the account
   page in cards (connection, re-scan, folder parse, providers, failures, folders, runs); System's
   login, client certificate and database pages; statistics, training progress and login page in
   the new style and translated; the fixed server messages translated (their English :content stays
   for logs); dark mode: theme colors instead of fixed grays, the logo blended into the surface, the
   charts drawn in the theme's colors.

* Review after step 4

Four independent reviews (data layer, server, interface, security) of all changes since the filter
fix found no security hole. Fixed afterwards: the scoring run replaces scores page by page instead of
deleting them all first (a deleted e-mail failed the whole run), skips scores below 1 % and marks
unfinished runs; "out of date" also follows a switch of the model type; the bulk bar's ✕ closes a
finished run's result; the column filters fit a phone screen; the language switch returns to the page
it was used on, also after a form post; saving an unknown category is refused; a page beyond the end
shows the last page; the checklist search finds non-ASCII capitals on SQLite; the Subject/From/To
checklists are only computed when the column filters are shown, the other suggestion counts load after
the category page; flag colors, "No category" (was "n/a"), the training labels and step states are
translated; model assignments stay below a confidence of 1.0; template values inside scripts are
encoded as JSON strings.

* Ideas for later

- *Remaining English texts*: the composed messages about folder parse runs, retries, moves and the
  clean-up (built from several parts in plauna.server), some validation messages of forms, and the
  generic "The request failed." of page scripts.

- *E-mail detail beside the list*: on the desktop the e-mail opens in a panel to the right of the
  list, so one can click through e-mails without leaving the list (and its filters and selection).
  Decided against for now in favour of the separate page; revisit after step 2.
